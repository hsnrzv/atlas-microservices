# atlas-backend (repository `atlas-microservices`)

Backend for **IKIGAI ATLAS**, a private personal planning system that turns long-term life goals into a
visual roadmap. This repository owns the Spring Boot application, its domain modules, the REST API
contract, the Flyway database migrations, the backend tests and the backend container image.

> **About the repository name.** The repository is called `atlas-microservices` for historical reasons.
> The backend is a **modular monolith**: one deployable Spring Boot application whose business
> capabilities are separate modules with enforced boundaries (Spring Modulith). There are no
> microservices, message brokers or per-module databases. See
> [ADR-0002](docs/adr/0002-modular-monolith-with-spring-modulith.md).

**Status:** Phase 1 (foundations). The application starts, connects to PostgreSQL through Flyway and
exposes health endpoints. There are **no domain modules, tables or feature endpoints yet**; they are
planned in [docs/plan/PLAN-BACKEND.md](docs/plan/PLAN-BACKEND.md).

## Prerequisites

| Tool | Version | Notes |
|---|---|---|
| JDK | 25 (LTS) | `JAVA_HOME` must point to a JDK 25 ([ADR-0008](docs/adr/0008-java-25-lts-runtime.md)). `./mvnw` uses `JAVA_HOME` before the `java` on the `PATH`. The build fails fast (Maven Enforcer) on Java < 25. |
| Docker | Docker Desktop or Docker Engine with Compose v2 | Needed for the local database (`compose.yaml`) and for the Testcontainers integration tests. |
| Maven | none | Use the Maven Wrapper (`./mvnw`, Maven 3.10.0). |

```bash
# macOS example; adjust the path to your JDK 25
export JAVA_HOME=$(/usr/libexec/java_home -v 25)
./mvnw -v
```

## Quick start

```bash
git clone git@github.com:hsnrzv/atlas-microservices.git
cd atlas-microservices
./mvnw spring-boot:run -Dspring-boot.run.profiles=local
curl -s http://localhost:8080/actuator/health   # {"groups":["liveness","readiness"],"status":"UP"}
```

The `local` profile starts [`compose.yaml`](compose.yaml) (PostgreSQL 18, **local-only** credentials
`atlas`/`atlas`, database `atlas`) through Spring Boot's Docker Compose support, connects to it, and runs
the Flyway migrations into schema `atlas`. Stopping the application stops the container; the data
volume is kept. Remove it with `docker compose down -v`.

If port 5432 is already used on your machine (for example by a natively installed PostgreSQL), pick
another host port:

```bash
ATLAS_DB_PORT=15432 ./mvnw spring-boot:run -Dspring-boot.run.profiles=local
```

The full local stack (frontend + backend + edge proxy on port 8000) is started from
[`atlas-infra/local`](https://github.com/hsnrzv/atlas-infra).

## Commands

| Task | Command |
|---|---|
| Full build: compile, unit + modularity tests, Testcontainers integration tests, enforcer, package | `./mvnw verify` |
| Unit and modularity tests only (no Docker) | `./mvnw test` |
| Run locally with the compose database | `./mvnw spring-boot:run -Dspring-boot.run.profiles=local` |
| Build the jar (skip tests) | `./mvnw -DskipTests package` → `target/atlas-backend.jar` |
| Build the container image | `docker build -t atlas-backend:local .` |
| Run the image against an existing database | see [Container image](#container-image) |
| Stop and delete the local database | `docker compose down -v` |
| Spring Modulith module documentation | generated by `./mvnw test` into `target/spring-modulith-docs/` |
| Coverage report (unit + integration, no gate yet) | generated by `./mvnw verify` into `target/site/jacoco/` |
| CycloneDX SBOM of the application dependencies | generated by `./mvnw package` into `target/classes/META-INF/sbom/application.cdx.json` (also in the jar) |

Integration tests (`*IT`) are skipped, not failed, when Docker is unavailable. CI requires them to run.

## Configuration

All environment-specific configuration comes from **environment variables**; there are no
`application-dev/staging/prod.yaml` files because those environments currently differ only in values,
not in structure. Secrets are never stored in this repository.

| Variable | Example | Purpose |
|---|---|---|
| `SPRING_PROFILES_ACTIVE` | `dev`, `staging`, `prod` | Profile name (`local` only on a developer machine). Profiles other than `local` log JSON (ECS). |
| `SPRING_DATASOURCE_URL` | `jdbc:postgresql://db-host:5432/atlas` | JDBC URL of database `atlas`. |
| `SPRING_DATASOURCE_USERNAME` | `atlas` | Database user (owner of schema `atlas`, or a user with `CREATE` on the database for the first migration). |
| `SPRING_DATASOURCE_PASSWORD` | from a secret store | Database password. |
| `JAVA_TOOL_OPTIONS` | `-XX:MaxRAMPercentage=75 -XX:+ExitOnOutOfMemoryError` | JVM options (image default shown). |

| Profile | Where | Database | Logs |
|---|---|---|---|
| `local` | developer machine | `compose.yaml` via `spring-boot-docker-compose` | human-readable |
| `dev`, `staging`, `prod` | Kubernetes (`atlas-infra`) | `SPRING_DATASOURCE_*` env vars | JSON (Elastic Common Schema) |
| tests | `./mvnw verify` | Testcontainers `postgres:18.6-alpine` | JSON |

Key runtime facts:

- HTTP port `8080`; API base path `/api/v1` (no endpoints yet).
- Health: `/actuator/health`, `/actuator/health/liveness`, `/actuator/health/readiness`; build info at
  `/actuator/info`. No other actuator endpoints are exposed.
- Errors use RFC 9457 Problem Details (`application/problem+json`).
- Graceful shutdown with a 20 s timeout per phase (fits a 30 s Kubernetes termination grace period).
- Hibernate never changes the schema (`ddl-auto=validate`); Flyway owns schema `atlas`
  (see [migration rules](src/main/resources/db/migration/README.md)).

## Container image

Multi-stage [`Dockerfile`](Dockerfile): build on `eclipse-temurin:25-jdk-noble`, run on
`eclipse-temurin:25-jre-noble` as non-root UID/GID `10001`, with Spring Boot layered extraction.

```bash
docker build -t atlas-backend:local \
  --build-arg VERSION=0.0.1-SNAPSHOT \
  --build-arg REVISION=$(git rev-parse HEAD) \
  --build-arg CREATED=$(date -u +%Y-%m-%dT%H:%M:%SZ) .

docker run --rm -p 8080:8080 \
  -e SPRING_PROFILES_ACTIVE=dev \
  -e SPRING_DATASOURCE_URL=jdbc:postgresql://host.docker.internal:5432/atlas \
  -e SPRING_DATASOURCE_USERNAME=atlas \
  -e SPRING_DATASOURCE_PASSWORD=atlas \
  atlas-backend:local
```

Build arguments `VERSION`, `REVISION` and `CREATED` only fill OCI labels. The application writes only to
`/tmp`; with a read-only root filesystem mount an `emptyDir` at `/tmp`. CI scans every image with Trivy
(fixable critical/high fail, exceptions in [`.trivyignore`](.trivyignore)) and uploads an image SBOM. Images are
not published yet:
publishing to `ghcr.io/hsnrzv/atlas-backend` is planned for Phase 2 (BE-2.4 in
[PLAN-BACKEND](docs/plan/PLAN-BACKEND.md), following `atlas-infra` ADR-0007).
